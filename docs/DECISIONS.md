# MySound — Architecture Decision Records (ADR)

سجل القرارات المعمارية والهندسية للمشروع.

---

## ADR 001: خيار التخزين السحابي وقاعدة البيانات (Supabase)
- **الحالة:** معتمد (Accepted)
- **السياق:** التطبيق مخصص لمالك فردي (Single Owner) مع مكتبة تحتوي مبدئيًا على أقل من 500 أغنية وتتطلب مصادقة آمنة، إدارة ملفات ثنائية (Audio & Images)، وقاعدة بيانات علائقية.
- **القرار:** اعتماد Supabase كمزود رئيسي:
  - PostgreSQL مع Row Level Security (RLS) لإحكام الحماية ومنع أي وصول غير مصرح به.
  - Supabase Storage لملفات الصوت والأغلفة باستخدام Buckets خاصة، بحيث لا يتم توليد أو كشف روابط عامة دائمة أبدًا، والاعتماد على Signed URLs قصيرة الأجل.
  - Supabase Auth مع حظر إنشاء الحسابات العامة (Sign Up) ليبقى التطبيق مقصورًا على حساب المالك.
- **الآثار والنتائج:** توفير بنية تحتية سحابية متينة دون الحاجة لبناء سيرفر مخصص في البداية، مع ضمان أعلى درجات الأمان وحماية حقوق الملكية.

## ADR 002: إطار العمل والواجهة الأمامية (Vue 3 + Vite + Tailwind CSS 4)
- **الحالة:** معتمد (Accepted)
- **السياق:** الحاجة إلى تطبيق ويب خفيف وسريع الاستجابة يعمل كـ PWA متكامل على أجهزة اللابتوب والهواتف مع دعم ثنائي اللغة (RTL/LTR) ومظهر داكن حديث.
- **القرار:** 
  - استخدام Vue 3 بنمط Composition API و`<script setup>` لأفضل تجربة تطوير وتنظيم للمنطق الصوتي المعقد.
  - Vite 6 كأداة بناء لبناء سريع ودعم PWA عبر `@vite-pwa/vite-plugin-pwa`.
  - Tailwind CSS 4 لتوفير نظام تصميم مرن ومتوافق مع الوضع الداكن الافتراضي (Dark Mode) ودرجات البرتقالي الدافئة.
  - Pinia لإدارة الحالة العامة (المشغل الصوتي، حالة التنزيل، إعدادات المستخدم).
- **الآثار والنتائج:** أداء فائق وتجربة مستخدم سلسة مع كود منظم وتدقيق صارم للأنواع عبر TypeScript.

## ADR 003: معمارية المشغل الصوتي الموحد (Singleton Audio Engine)
- **الحالة:** معتمد (Accepted)
- **السياق:** يجب أن يستمر تشغيل الصوت دون أي انقطاع أثناء تنقل المستخدم بين شاشات التطبيق المختلفة، مع دعم كامل للتحكم من لوحة المفاتيح والـ Media Session API في الهاتف وشاشة القفل.
- **القرار:** إنشاء خدمة مشغل صوتي مركزية واحدة (Singleton Audio Engine) تدير عنصر `HTMLAudioElement` واحد في الذاكرة وموصولة بـ Pinia Store. لا يُسمح للمكونات بإنشاء كائنات صوت مستقلة لمنع تداخل وتشويش الصوت.
- **الآثار والنتائج:** تشغيل مستقر وقدرة على التحكم التام في موضع الأغنية، وقوائم الانتظار، واستئناف التشغيل التلقائي بعد انتهاء صلاحية الروابط الموقعة.

## ADR 004: استراتيجية التخزين دون اتصال (Offline Strategy & IndexedDB)
- **الحالة:** معتمد (Accepted)
- **السياق:** يحتاج المستخدم لتشغيل الأغاني التي اختار تنزيلها حتى بعد قطع الإنترنت وإعادة تشغيل التطبيق، مع عدم افتراض توفر OPFS بشكل موحد عبر جميع المتصفحات والمنصات (خاصة هواتف iOS القديمة).
- **القرار:**
  - المستوى الأول (App Shell): عبر Service Worker من خلال Vite PWA لتخزين ملفات التطبيق الثابتة والتشغيل بدون إنترنت.
  - المستوى الثاني (Downloaded Music): تخزين ملفات الصوت المحملة في IndexedDB كـ Blobs، وحفظ البيانات الوصفية والفهارس وحالة التنزيل الخاصة بالجهاز الحالي فقط.
  - عدم استخدام السحابة في حال انقطاع الاتصال إذا لم تكن الأغنية منزلة فعليًا.
  - تنزيل الأغنية على جهاز معين يخص ذلك الجهاز فقط ولا يفرض تنزيلها على الأجهزة الأخرى.
- **الآثار والنتائج:** استقرار ممتاز وتوافق واسع مع جميع المتصفحات الرئيسية دون مخاطر تآكل التخزين غير المتوقع.

## ADR 005: ثنائية اللغة ودعم اتجاه النص الحقيقي (Bilingual & Real RTL)
- **الحالة:** معتمد (Accepted)
- **السياق:** دعم العربية كلغة أساسية أولى مع الإنجليزية، مع مراعاة اتجاه الأيقونات، والحركة، وتناسق الخطوط (Cairo / Inter).
- **القرار:** بناء نظام تدويل مركزي خفيف ومباشر مع ضبط سمة `dir` على مستوى عنصر `<html>` (`rtl` للعربية و `ltr` للإنجليزية) وتخزين التفضيل في `localStorage` مع تطبيق محاذاة وتنسيقات مرنة باستخدام فئات Tailwind المنطقية مثل `start`, `end`, `ms-`, `me-`.
- **الآثار والنتائج:** واجهة طبيعية تمامًا للمستخدم العربي دون تشوه في التصميم أو تعاكس في الأيقونات.

## ADR 006: سياسات الأمان وتوليد الروابط الموقعة للتخزين السحابي (RLS & Signed URLs)
- **الحالة:** معتمد (Accepted)
- **السياق:** تتطلب ملفات الصوت الخاصة بالمستخدم ألا تكون عامة ومتاحة لأي شخص يملك الرابط الدائم، مع ضمان عدم تسريب أي مفاتيح حساسة مثل `service_role`.
- **القرار:**
  - جعل مجلدات التخزين `audio` و `covers` خاصة بالكامل (`public: false`).
  - تنظيم ملفات الصوت داخل مجلدات تحمل معرّف المالك `auth.uid()`.
  - تطبيق سياسات Storage RLS تسمح فقط للمستخدم المصادق عليه بالقراءة والرفع على مجلده.
  - تشغيل الملفات عبر الروابط الموقعة قصيرة الصلاحية (`createSignedUrl`) لمدة 3600 ثانية للملفات الصوتية و 7200 ثانية للأغلفة، وتجديدها ديناميكيًا عند انتهاء الصلاحية.
- **الآثار والنتائج:** حماية تامة من القرصنة أو الوصول المباشر، وعدم إمكانية تحميل أي ملف دون جلسة مالك صالحة.
