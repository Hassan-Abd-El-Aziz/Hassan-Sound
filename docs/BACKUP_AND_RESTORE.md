# استراتيجية النسخ الاحتياطي والاستعادة — MySound

دليل شامل للمهندس والمالك لتوثيق وتنفيذ عمليات النسخ الاحتياطي لقاعدة البيانات، وملفات التخزين السحابي، والبيانات الوصفية (Metadata Manifest).

---

## 1. الفلسفة الأساسية للنسخ الاحتياطي في MySound

> [!IMPORTANT]
> **قاعدة ذهبية:** تصدير ملف البيانات الوصفية (Metadata Manifest) لا يُعتبر وحده نسخة احتياطية كاملة للمكتبة الموسيقية! بل هو خريطة وهيكل يربط المسارات والفنانين والقوائم بالأرقام الثنائية وبصمات SHA-256. يجب دائمًا أخذ نسخة احتياطية من **الملفات الصوتية الأصلية في Supabase Storage**.

---

## 2. مستويات النسخ الاحتياطي الثلاثة

```
┌────────────────────────────────────────────────────────┐
│ 1. Storage Buckets (ملفات الصوت MP3/FLAC والأغلفة)    │
├────────────────────────────────────────────────────────┤
│ 2. PostgreSQL Database (الجداول والسياسات والمستخدمين)  │
├────────────────────────────────────────────────────────┤
│ 3. JSON Library Manifest (البيانات الوصفية والقوائم)    │
└────────────────────────────────────────────────────────┘
```

---

## 3. المستوى الأول: النسخ الاحتياطي للملفات الصوتية (Supabase Storage)

الملفات الصوتية مخزنة داخل Bucket خاص اسمه `audio` وملفات الأغلفة في `covers`.

### طريقة أخذ نسخة باستخدام Supabase CLI:
```bash
# تسجيل الدخول وتحديد المشروع
supabase login
supabase link --project-ref your-project-id

# نسخ كافة الملفات الصوتية محلياً إلى القرص الصلب
supabase storage cp -r ss:///audio ./backup_storage/audio/
supabase storage cp -r ss:///covers ./backup_storage/covers/
```

أو استخدام أي أداة متوافقة مع S3 (مثل AWS CLI أو Cyberduck) عبر مفاتيح S3 credentials المتاحة في لوحة تحكم Supabase.

---

## 4. المستوى الثاني: النسخ الاحتياطي لقاعدة البيانات (PostgreSQL)

### النسخ التلقائي:
- تدعم منصة Supabase النسخ الاحتياطي اليومي التلقائي (Daily Backups) و Point-in-time Recovery (PITR).

### النسخ اليدوي الكامل عبر `pg_dump`:
```bash
pg_dump "postgresql://postgres:[YOUR-PASSWORD]@db.[PROJECT-ID].supabase.co:5432/postgres" \
  --clean \
  --if-exists \
  --quote-all-identifiers \
  --schema=public \
  -f "mysound_db_backup_$(date +%Y%m%d).sql"
```

## 5. المستوى الثالث: تصدير واستيراد الـ JSON Manifest من واجهة التطبيق

يوفر تطبيق MySound أداة تصدير واستيراد مدمجة من صفحة **الإعدادات والتخزين (Settings)**:

### محتوى ملف `mysound-manifest-YYYY-MM-DD.json`:
- `manifest_version`: إصدار البروتوكول (`1.0`).
- `owner_id`: معرّف المالك.
- `summary`: إحصائيات عدد الأغاني، الفنانين، الألبومات، وقوائم التشغيل.
- `artists` و `albums`: كافة السجلات الفريدة.
- `tracks`: كل أغنية ببياناتها (`title`, `artist_name`, `album_title`, `duration_ms`, `storage_path`, `content_hash`).
- `playlists`: القوائم وربطها بمعرفات المسارات.
- `favorites`: قائمة معرّفات الأغاني المفضلة.

### خطوات الاستعادة والتحقق (Restore Test):
1. عند الانتقال إلى بيئة جديدة أو مشروع Supabase بديل:
2. نفّذ ملفات الـ migrations لإنشاء الجداول الـ 13 و Buckets التخزين.
3. ارفع الملفات الصوتية إلى الـ Bucket بنفس مساراتها `storage_path`.
4. ارفع ملف الـ Manifest عبر زر **"استيراد الـ Manifest"** من صفحة الإعدادات.
5. سيقوم التطبيق بالتحقق من صحة الملف ودمج المسارات والفنانين والقوائم فورًا.
